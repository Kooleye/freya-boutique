# Фрейя — мобильный бутик (многостраничная версия)

Статичный сайт без сборки: HTML + CSS + ванильный JS. Базовая ширина 393px (iPhone), корректно 375–430px, учтены safe-area-inset.

## Файлы

- `index.html` — все шесть экранов (каждый — отдельная `<section class="view">`)
- `style.css` — стили и токены цветов/размеров с макета
- `script.js` — роутер, каталог, корзина, галерея, валидация формы
- `railway.json`, `package.json` — деплой на Railway
- `freya-preview.html` — ОДИН самодостаточный файл (CSS и JS вшиты): открыть двойным кликом для быстрого просмотра
- `build-preview.js` — пересобрать превью после правок: `node build-preview.js`

## Страницы (hash-роутинг)

| Адрес | Страница |
|---|---|
| `#/` | Главная — только Новинки |
| `#/catalog/all` | Каталог — все товары |
| `#/catalog/dresses` \| `suits` \| `outerwear` \| `tops` | Подразделы: Платья, Костюмы, Верхняя одежда, Топы |
| `#/product/<id>` | Карточка товара (Описание, Состав и уход) |
| `#/cart` | Корзина — кнопка «Оформить заказ» ведёт дальше |
| `#/checkout` | Формирование заказа — имя и телефон, как на макете |
| `#/done` | Заказ принят |

Гамбургер слева вверху открывает боковое меню: Весь каталог, Новинки, Платья, Костюмы, Верхняя одежда, Топы и Корзина.
Иконка корзины справа ведёт на `#/cart`, счётчик обновляется автоматически.
На карточке товара клик по фото открывает полноэкранную галерею (5 фото, стрелки, точки, свайп, закрытие крестиком или Esc).

## Локальный запуск

```bash
npx serve . -l 3000
```

Или просто открыть `freya-preview.html` в браузере.

## Деплой на Railway

1. Залить папку в GitHub-репозиторий → New Project → Deploy from GitHub repo.
2. Или через CLI: `npm i -g @railway/cli && railway login && railway init && railway up`.
3. Settings → Networking → Generate Domain.

Масштабирование (двойной тап и pinch) отключено, в галерее фото меняются без анимации перелистывания.

Фото товаров — заглушки picsum.photos, шрифт заголовков — Google Fonts; оба ресурса грузятся из сети устройства.

## Админка

Адрес: `/admin.html` (например `https://ваш-сайт.up.railway.app/admin.html`).
Пароль по умолчанию: **242564** (меняется в разделе «Настройки»).
Страница закрыта от поисковиков (`robots: noindex`) и нигде не пролинкована с сайта.

### Что настраивается

- **Товары**: добавление, дублирование, удаление, порядок (↑/↓), поиск.
- **Фото**: загрузка с телефона или по ссылке, кнопка ★ — сделать фото основным, ←/→ — порядок, × — удалить.
- **Цены**: цена и цена до скидки (зачёркнутая на сайте).
- **Галочки**: «Новинка», «По акции» (бейдж АКЦИЯ), «Показывать на сайте».
- **Карточка**: описание, состав и уход (по строкам), оттенки, размеры, название цвета.
- **Категории**: добавление, переименование, иконка, порядок, удаление с переносом товаров.
- **Тексты сайта**: название магазина, золотая полоса, две строки подписи.

### Как правки попадают на сайт

1. Всё, что вы меняете в админке, сразу сохраняется в браузере этого устройства (localStorage, лимит ≈ 5 МБ) — сайт на том же устройстве уже показывает изменения.
2. Чтобы изменения увидели все посетители: раздел «Данные» → «Скачать catalog.json».
3. Положить `catalog.json` в корень проекта (рядом с `index.html`) и задеплоить на Railway.
4. Сайт сам подхватит `catalog.json` при загрузке.

Кнопка «Сбросить к заводским данным» убирает локальные правки и возвращает то, что лежит в `catalog.json` / `data.js`.

### Файлы

- `admin.html`, `admin.css`, `admin.js` — панель управления.
- `data.js` — каталог по умолчанию и общий слой данных для сайта и админки.

## Оформление заказа

В корзине главная кнопка — «Оформить заказ» (на пустой корзине она скрыта),
ниже — «Продолжить покупки». Кнопка ведёт на отдельную страницу `#/checkout`:
сумма заказа, поля «Имя» и «Телефон», галочка согласия, кнопка «Оформить заказ»
и подпись «Ваши данные под защитой».

Телефон вводится по маске `+7 (999) 999-9999`. Проверка: имя не пустое,
в телефоне 10 цифр после кода, галочка отмечена. После отправки открывается
экран «Заказ принят», корзина очищается. Зайти на `#/checkout` с пустой корзиной нельзя —
сайт возвращает в корзину.

Кнопка «Добавить в корзину» в карточке товара сразу переводит в корзину.

## Плавная прокрутка

Дрожание при быстром долистывании давали три вещи, и все три убраны:

1. Приближение фото по `:active` — палец во время скролла «нажимал» на карточки,
   и каждая пересчитывала масштаб. Теперь этот эффект только для мыши (`hover`).
2. Обработчик запрета двойного тапа отменял `touchend` подряд и рвал инерцию.
   Теперь он срабатывает только на два тапа в одну точку без движения пальца.
3. Отдача у краёв и автоподстройка позиции: `overscroll-behavior-y: none`
   и `overflow-anchor: none`. Смена экранов теперь только проявление, без сдвига по вертикали.

В полноэкранном режиме кадр фиксированный — 3:4 на всю ширину экрана. Все фото
и видео занимают один и тот же прямоугольник (`object-fit: cover`), поэтому при листании
ничего не прыгает. Названия и цены внизу больше нет — только стрелки, точки и крестик.

## Видео в карточке товара

Ролики больше не грузятся сами. На видео-кадре видна картинка-постер и одна круглая
кнопка «Смотреть видео» — и в карточке, и в полноэкранном режиме. Файл скачивается
только после нажатия (`preload="none"`), поэтому страница открывается быстро
и трафик клиента не тратится впустую. После нажатия видео идёт по кругу как
«живая картинка»: ни паузы, ни полосы времени, ни регулятора громкости на нём нет.

- В карточке видео идёт после фотографий: свайп, стрелки и точки листают фото и видео одной лентой.
  Точка видео отличается золотой обводкой, под фото меняется подсказка на «Видео товара».
- На карточках в каталоге никаких подписей поверх фото нет — только само фото 1:1.
- Как только ушли с видео-кадра или со страницы, ролик останавливается
  и полностью выгружается из памяти (у `<video>` снимается адрес файла).
- Фото и название товара стыкуются ровной линией: скругления по бокам
  и наложения блока на фото больше нет.

### Как добавить видео

Админка → «Товары» → «Изменить» → раздел «Видео».

1. «Качество» — 720p · 30 кадров (по умолчанию) или 1080p · 30 кадров.
2. «Загрузить видео с устройства» — ролик пережимается прямо в браузере:
   большая сторона до 1280 px (720p) или 1920 px (1080p), 30 кадров/с,
   битрейт 4 Мбит/с (720p) или 7 Мбит/с (1080p), со звуком 128 кбит/с,
   берутся первые 15 секунд. Сжатие идёт в реальном времени: сколько секунд
   в ролике — столько и ждём, страницу в это время закрывать нельзя.
   Первый кадр сохраняется постером — он виден, пока видео грузится.
   На плитке подписано итоговое качество и вес готового ролика.
3. «Или ссылка на видео (.mp4)» — ссылка ничего не весит. Удобно для длинных
   роликов: положите файл рядом с index.html и впишите его имя, например promo.mp4.
4. Стрелки ← → меняют порядок видео, ✕ удаляет. После правок — «Сохранить».

### Формат: только MP4 (H.264)

iPhone не умеет открывать WebM — такой ролик на телефоне выглядит чёрным экраном,
хотя на компьютере всё играет. Поэтому админка больше никогда не создаёт WebM:

- если браузер умеет пережимать в MP4 (Safari на Mac и iPhone) — ролик сжимается;
- если не умеет (Chrome на ПК умеет только WebM) — файл сохраняется как есть,
  без пережатия (до 40 МБ), чтобы остаться в формате MP4;
- если ролик тяжелее 40 МБ — админка предложит взять файл полегче или добавить ссылкой.

Если в каталоге всё же остался ролик в неподдерживаемом формате, сайт вместо
чёрного экрана покажет понятное сообщение «Телефон не открывает формат этого ролика
— перезалейте видео в админке» и вернёт картинку-постер.

### Звук

Звуковая дорожка записывается вместе с видео (128 кбит/с). В редакторе товара есть
галочка «Записать со звуком» — снимите её, если ролик нужен беззвучным.
На плитке подписано «со звуком» или «без звука».

На сайте видео стартует тихо: запуск со звуком ограничен во всех
браузерах (правило Safari и Chrome, обойти его нельзя). На кадре есть одна круглая
кнопка с динамиком: в карточке — справа внизу, в полноэкранной галерее — слева вверху.
Один тап — и звук включён; выбор запоминается и действует для всех следующих роликов
(ключ localStorage `freya_video_sound`). У роликов, записанных без звука, кнопка не показывается.
Никаких других элементов плеера нет: паузы, полосы времени и регулятора громкости.


### Где хранятся ролики

720p-видео не помещается в localStorage (там всего ~5 МБ), поэтому сами ролики
лежат в IndexedDB (обычно сотни мегабайт, на iOS — около трети свободного места),
а в каталоге хранится только ссылка вида `idb:v...` и маленький постер.
В разделе «Данные» видно число видео и строка «Видео в браузере» с занятым местом.
Неиспользуемые ролики удаляются автоматически после сохранения товара.

Важно: IndexedDB — хранилище одного браузера. Чтобы видео увидели все посетители:
«Данные» → «Скачать catalog.json» (ролики подмешиваются в файл) → положить файл
в корень рядом с index.html → залить на Railway. Файл получается тяжёлым, поэтому
для многих роликов лучше класть видеофайлы в проект и добавлять их ссылками.
При загрузке catalog.json через «Загрузить catalog.json» видео из файла автоматически
перекладывается в IndexedDB, чтобы не занимать лимит localStorage.
