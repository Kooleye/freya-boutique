# Переезд «Фрейи» на Timeweb Cloud + S3

Это инструкция «сверху вниз»: от пустого сервера до работающего магазина с админкой.
Все команды можно копировать целиком. Если что-то пойдёт не так — в конце есть раздел «Если что-то не работает».

---

## 1. Что изменилось по сравнению с версией на Railway

| | Было | Стало |
|---|---|---|
| Каталог товаров | в браузере (localStorage), у каждого устройства свой | файл `catalog.json` на сервере, вне папки с кодом |
| Фото | base64 внутри каталога | webp в S3 + отдельная миниатюра для списков |
| Видео | в IndexedDB браузера, пережималось телефоном | mp4 в S3, пережимает сервер (ffmpeg) |
| Качество видео | 720p по умолчанию, 15 секунд, «на глаз» | **всегда 1080p, 30 кадров, максимум 20 секунд** |
| Пароль админки | в коде сайта (его видел любой) | scrypt-хеш на сервере + HttpOnly-cookie |
| Обновление сайта | заливка перезаписывала всё | код в `releases/`, данные в `data/` — обновление их не трогает |
| Зависимости npm | `serve` | **нет ни одной** — только Node и системный ffmpeg |

Про видео подробно: раньше ролик пережимался в браузере через `MediaRecorder` (canvas + `captureStream`),
а если браузер не умел mp4 — исходник сохранялся вообще без сжатия. Отсюда и «весит много».
Теперь браузер только отдаёт файл, а сервер приводит его к одному виду:

```
короткая сторона 1080 (длинная ≤ 1920) · 30 кадров · -t 20 (обрезка)
H.264 high 4.1 · crf 23 · maxrate 4500k · +faststart
AAC 128k 48 кГц стерео (или совсем без звука, если выключили галочку)
+ постер-кадр в webp
```

`+faststart` — это важно: без него телефон качает весь файл, прежде чем показать первый кадр.
Поворот из метаданных телефона учитывается, вертикальное видео остаётся вертикальным.

## 2. Что заказать в Timeweb

1. **S3-хранилище** (Облачное хранилище) — здесь будут лежать фото и видео.
   - Тип доступа: **публичный** (файлы отдаются покупателям напрямую).
   - Запишите: имя бакета, `Access Key`, `Secret Key`.
   - Адрес: `https://s3.twcstorage.ru`, регион `ru-1`.
2. **CDN** для этого бакета (по желанию, но лучше включить) — видео будет открываться быстрее,
   потому что раздаётся из точки рядом с покупателем.
3. **Облачный сервер (VPS)** — 2 ядра / 2 ГБ ОЗУ / 40 ГБ диска хватает с запасом.
   Ubuntu 24.04. Диск нужен маленький: тяжёлые файлы лежат в S3, на сервере только каталог и текст.
4. **Домен** и A-запись на IP сервера.

## 3. Подготовка сервера (один раз)

Подключитесь к серверу по SSH и выполните:

```bash
apt update && apt install -y git
git clone <ваш-репозиторий> /root/freya-src   # или загрузите архив и распакуйте
cd /root/freya-src
bash deploy/setup-server.sh
```

Скрипт поставит Node.js 20, **ffmpeg**, nginx, certbot, создаст пользователя `freya`
и раскладку папок:

```
/srv/freya
├── releases/           # версии кода (последние 5)
├── current -> releases/2026-08-22-101500   # активная версия
├── .env                # настройки и ключи (только root/freya, chmod 600)
└── data/               # НИКОГДА не перезаписывается при обновлении
    ├── catalog.json    # каталог товаров
    ├── backups/        # автокопии каталога (60 последних правок)
    ├── daily/          # суточные архивы (backup.sh)
    ├── media/          # медиа, если работаете без S3
    └── tmp/            # черновики загрузок, чистятся сами
```

## 4. Файл настроек `.env`

```bash
cp /root/freya-src/.env.example /srv/freya/.env
nano /srv/freya/.env
chmod 600 /srv/freya/.env
```

Минимум, что нужно заполнить:

```env
ADMIN_PASSWORD=придумайте-длинный-пароль
HTTPS_COOKIES=1

STORAGE_DRIVER=s3
S3_BUCKET=имя-вашего-бакета
S3_ACCESS_KEY=...
S3_SECRET_KEY=...

# Адрес, по которому покупатель забирает фото и видео.
# С CDN:      MEDIA_BASE_URL=https://cdn-xxxx.twcstorage.ru
# Без CDN:    оставьте пустым — ссылки соберутся на адрес бакета
MEDIA_BASE_URL=
```

Чтобы пароль не лежал в файле открытым текстом:

```bash
cd /srv/freya/current
npm run hash-password -- ваш-пароль
# полученную строку ADMIN_PASSWORD_HASH=... вставьте в .env, а ADMIN_PASSWORD удалите
```

## 5. Выкладка кода

```bash
cd /root/freya-src
bash deploy/deploy.sh
```

Скрипт: проверит синтаксис, скопирует код в новый `releases/<дата>`, переключит `current`,
поставит systemd-юнит, перезапустит сервис и дёрнет `/api/health`.
Если сервис не поднялся — покажет логи и выйдет с ошибкой, `current` при этом остаётся на прошлой версии.

Дальше nginx:

```bash
cp /srv/freya/current/deploy/nginx.conf /etc/nginx/sites-available/freya
nano /etc/nginx/sites-available/freya          # замените example.com на свой домен
ln -sf /etc/nginx/sites-available/freya /etc/nginx/sites-enabled/freya
rm -f /etc/nginx/sites-enabled/default
nginx -t && systemctl reload nginx
certbot --nginx -d ваш-домен.ru -d www.ваш-домен.ru
```

Проверка:

```bash
systemctl status freya
cd /srv/freya/current && npm run health
```

`npm run health` должен показать: хранилище работает, ffmpeg есть, каталог на месте.

## 6. Первый вход в админку

1. Откройте `https://ваш-домен.ru/admin.html`
2. Введите пароль из `.env`.
3. Загрузите товар: фото, потом видео. В подсказке под кнопкой видео так и написано:
   **1080p · 30 кадров · до 20 секунд**, выбирать качество больше не нужно.
4. Нажмите «Сохранить» — каталог уедет на сервер, и его увидят все устройства сразу.

Что происходит при загрузке видео:
телефон отдаёт файл (видно полосу «Отправляю ролик — 47%»), потом сервер пишет
«Сервер пережимает видео в 1080p…» и в конце показывает результат: `Видео 1080p · 20 сек · 3.4 МБ`.
Если ролик был длиннее — в сообщении будет «обрезано до 20 сек».

## 7. Перенос старых товаров

Если на Railway уже есть заполненный каталог:

1. В старой админке нажмите «Выгрузить JSON».
2. Загрузите файл на сервер, например в `/tmp/old-catalog.json`.
3. Посмотрите план переноса (ничего не меняя):

```bash
cd /srv/freya/current
npm run migrate -- /tmp/old-catalog.json
```

4. Выполните перенос:

```bash
npm run migrate -- /tmp/old-catalog.json --write
```

Фото (base64) уедут в S3 автоматически. **Видео вернуть нельзя** — они лежали только
в IndexedDB браузера, на сервер никогда не попадали. Скрипт напечатает список товаров,
у которых надо залить ролик заново.

## 8. Обновления сайта в будущем

```bash
cd /root/freya-src && git pull
bash deploy/deploy.sh
```

Каталог и медиа не пострадают: они в `/srv/freya/data` и в S3, а выкладка работает
только с `/srv/freya/releases`. Если новая версия не понравилась:

```bash
bash deploy/deploy.sh --rollback
```

Резервные копии:

```bash
crontab -e
# 30 3 * * * /srv/freya/current/deploy/backup.sh >> /var/log/freya-backup.log 2>&1
```

Лишние файлы в хранилище (удалили товар — медиа осталось):

```bash
npm run gc-media            # показать
npm run gc-media -- --yes   # удалить
```

## 9. Сколько это весит и как быстро работает

Один ролик 1080p/30fps/20 сек при crf 23 — примерно **2–5 МБ**.
100 товаров × (4 фото ≈ 150 КБ + 1 ролик ≈ 4 МБ) ≈ **0,5 ГБ** в хранилище.

На сам сайт видео почти не влияет, потому что:

- в карточках грузятся миниатюры (`.thumb.webp`, ~500 px), а не полные фото;
- видео не начинает качаться, пока покупатель не нажал play (эта логика сохранена);
- у превью подставлен постер-кадр в webp — 5–15 КБ вместо мегабайтов;
- файлы отдаёт S3/CDN, а сервер занят только каталогом.

Переживать за нагрузку не нужно: сервер тратит силы только в момент загрузки ролика
в админке (перекодирование 20 секунд занимает считанные секунды).

## 10. Если что-то не работает

| Симптом | Что делать |
|---|---|
| Админка пишет «Нужен вход в панель» | сессия истекла (12 часов) — войдите снова |
| «Видео не обработалось: ffmpeg…» | `apt install -y ffmpeg`, затем `systemctl restart freya` |
| «S3 PUT 403» | неверные ключи или бакет — проверьте `.env`, затем `npm run health` |
| Фото не открываются на сайте | неверный `MEDIA_BASE_URL` или бакет не публичный |
| Каталог не сохраняется, ошибка про base64 | загружаете старый экспорт — сначала `npm run migrate` |
| Сервис падает | `journalctl -u freya -n 50 --no-pager` |
| Нужно откатить каталог | файлы в `/srv/freya/data/backups/` — скопируйте нужный в `catalog.json` и `systemctl restart freya` |

Локальная проверка без S3 (удобно для тестов на своём компьютере):

```bash
npm run dev     # STORAGE_DRIVER=local, медиа складывается в data/media
```
